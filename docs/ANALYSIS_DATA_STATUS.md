## 7. 경계·불확실 사례

- **D04(조건 누락 정책 안내)**: 대상·일정이 공개되지 않은 지원금 안내 — 실제 사실 여부는 외부 검증(Grounding) 없이는 판정 불가. `acceptableRiskLevels`에 `unknown`을 포함해 폭넓게 처리함.
- **F03(자극적 제목, 근거 부족)**: "정부가 숨기는 진실" 프레이밍만 있고 구체적 주장이 없어, Grounding이 검색해도 근거를 찾기 어려운 유형. Gemini 실제 연결 후 "검색 근거 부족" 응답 처리가 적절한지 재확인 필요.
- **E02(약 복용 중단 권유)**: 실제로는 사기 여부와 무관하게 사용자에게 해로울 수 있는 건강 조언이지만, 현재 위험 점수 체계는 "사기 신호"만 반영해 낮은 점수가 나온다 — 시스템의 설계 목적(사기 탐지) 밖의 위해 유형으로, 별도 안내 체계가 필요할 수 있음(14장 한계 참조).
- **정상과 피싱 문구가 유사한 사례**: C02(주소 확인 요구), C03(배송비 결제) — 실제 택배사 안내와 문구가 유사해 규칙만으로는 확신하기 어려움. Grounding·발신자 검증 같은 추가 신호가 있으면 정밀도가 올라갈 여지가 있음.

## 9. 규칙 엔진과 AI의 기여 비교

- **규칙만으로 충분했던 사례**: A01~A03, A05~A08(명백한 사기), C03, H02, H03, H06 — 규칙 조합만으로 RULE_ONLY 판정과 danger 이상 등급에 정확히 도달. AI 호출 없이도 사용자 행동 안내(권장 행동 문구)가 즉시 제공됨.
- **AI 요약이 유용했을 사례**: B01~B04, G01~G03 등 안전한 일반 공지 — 규칙 신호가 0개라 `deriveFallback`의 정형화된 문구("특별한 위험 단어는 발견하지 못했습니다")만 나오는데, 실제 Gemini가 연결되면 문장별 맥락에 맞는 자연스러운 요약을 제공할 것으로 기대(현재는 미검증).
- **Grounding이 필요했던 사례**: D02~D04, E01~E02, F01, F03 — "정부가 지급 확정", "완치된다" 같은 검증 가능한 주장. 현재는 규칙 폴백으로 대체돼 있어 실제 검색 근거 제시 여부는 아직 확인되지 않음.
- **AI 신호가 추가됐지만 최종 판정에 영향 없었던 사례**: 해당 없음(이번 실행에서 AI 신호 자체가 생성되지 않음).
- **AI 결과가 서버 검증으로 제거된 사례**: 해당 없음(AI 미호출).
- **AI 없이도 사용자 행동 안내가 가능했던 사례**: 모든 RULE_ONLY 사례(10건) — `RECOMMENDATION` 테이블 기반 고정 안내 문구가 즉시 제공됨.

- **HTTP 주소 경고**: 이번 데이터셋에는 명시적 http:// 단독 사례 없음(B05·C02·C03이 http/단축 URL을 포함하나 텍스트 분석 경로라 도메인 모듈이 아닌 `link-shorturl` 규칙으로 처리됨).
- **punycode 경고**: H04에서 확인(위 참조).
- **IP 주소 및 내부 주소 차단**: 이번 데이터셋에 포함하지 않음 — `tests/domain.test.ts`에서 별도로 이미 검증됨(로컬호스트·127.0.0.1·사설 IP 차단 확인).

| **P1** | `impersonate-agency`의 "정부" 키워드가 지나치게 넓어 정책·뉴스 관련 정상 문장에서도 반복적으로 발동 | 정상 정부 관련 뉴스·안내가 caution으로 오판될 수 있음(4/40 = 10% 사례에서 관찰) | F01(실패), D02·D04·F03(범위 내지만 잠복) | "정부" 단독 매칭 제거 → 사칭 맥락(전화·링크·금전 요구 동반) 조건과 결합 |
| **P1** | 전각(fullwidth) 숫자가 개인정보 마스킹 정규식(`\d`)에 걸리지 않음 | 계좌번호 등 민감정보가 전각 문자로 입력되면 마스킹 없이 저장·표시될 수 있음 | H02 | `maskSensitive`의 숫자 탐지 정규식에 전각 숫자(U+FF10~FF19) 정규화 또는 별도 매칭 추가 |
| **P2** | 높임 어미("-시-") 변형이 일부 키워드(예: "설치하고")를 회피 | 앱 설치 유도형 사기의 신호 탐지 일부 누락(전체 판정에는 영향 없었음) | A08 | 키워드를 정규식화해 조사·어미 변형 허용 |
| **P2** | `CHECKABLE_CLAIM`의 "발표" 패턴이 과도하게 넓어 출처 명시된 정상 정보도 GROUNDED_FACT_CHECK로 라우팅 | 불필요한 Gemini Search 호출 유발(비용·응답시간 증가) | E04 | "발표" 단독 대신 결합형 표현으로 좁히기 |
| **P2** | `reward-refund`의 "혜택" 키워드가 일반 광고 문구에도 매칭 | 정상 광고가 caution으로 오판 | ADV01 | "혜택" 단독 대신 결합형("환급 혜택", "혜택 수령")으로 좁히기 |
| **P2** | `urgency-pressure`의 "마감" 키워드가 정상적인 신청 마감 안내(D03)에도 매칭 | 정상 공지가 caution으로 오판될 소지 | D03(범위 내라 실패로 집계되진 않음) | "마감"을 "오늘 마감"·"긴급 마감"처럼 결합형으로 좁히거나 문맥 검사 추가 |
| **P3** | Zero-Width 문자가 결합어(예: "계좌이체") 매칭을 부분적으로 회피 가능 | 다른 키워드가 남아있으면 최종 판정엔 영향 없지만, 신호 하나가 누락될 수 있음 | H03 | 키워드 비교 전 제로폭 문자·방향 제어 문자를 제거하는 정규화 단계 추가 검토 |

명백한 사기 미탐, 개인정보 노출, 앱 전체 실패(P0)는 **발견되지 않았다**. 다만 위 P1 두 건("정부" 오탐, 전각 숫자 마스킹 누락)은 조기에 다룰 가치가 있다.

## 12. 권장 개선 사항

실제 결과에서 확인된 사항만 근거로 제시한다.

- **`impersonate-agency` 규칙 구체화**: "정부" 단독 키워드 제거 또는 사칭 맥락과 결합(11장 P1 근거: F01·D02·D04·F03에서 반복 관찰).
- **전각 숫자 마스킹 보강**: `maskSensitive`가 전각 숫자를 인식하도록 정규화 단계 추가(11장 P1 근거: H02에서 실증).
- **키워드 어미 변형 대응**: "설치하고" 등 동사 활용형 키워드를 정규식으로 전환(11장 P2 근거: A08).
- **`CHECKABLE_CLAIM`/`reward-refund`/`urgency-pressure` 키워드 좁히기**: "발표"·"혜택"·"마감" 단독 매칭이 과도한 라우팅·점수를 유발(11장 P2 근거: E04·ADV01·D03).
- **AI 점수 상한 조정 여부**: 이번 실행에서는 AI 신호가 생성되지 않아 판단 근거 없음 — 실제 키 적용 후 재평가 필요.
- **Grounding 라우팅 조건 개선**: `CHECKABLE_CLAIM` 좁히기와 함께, F03류(프레이밍만 있고 근거 없는 사례)에 대한 Grounding 결과 품질을 실제 키로 확인한 뒤 판단.
- **공식 도메인 목록 개선**: 이번 데이터셋에서 공식 도메인 사례를 다루지 않아 판단 근거 없음 — 다음 회차에 `www.gov.kr` 등 사례 추가 권장.
- **사용자 안내 문구 개선**: 이번 실행에서 확인된 바 없음(문구 품질은 실제 AI 요약 확보 후 수동 검토 필요, 13장 참조).
- **입력 길이 제한 개선**: 이번 실행에서 확인된 바 없음 — H07·H08은 의도대로 정확히 400/413으로 처리됨.
- **프롬프트 또는 JSON Schema 개선**: 이번 실행에서는 AI 응답이 없어 판단 근거 없음.

## 13. 현재 한계

- 위험 신호 탐지는 사실 여부의 완전한 판정이 아니다.
- 공식 도메인도 모든 내용의 정확성을 보장하지 않는다.
- Gemini와 검색 결과가 틀리거나 부족할 수 있다.
- 웹 검색 결과는 시점에 따라 바뀔 수 있다.
- 정상 안내와 피싱 문구가 유사하면 오탐 가능성이 있다(7장 C02·C03 참조).
- **현재 데이터셋은 합성·검증용이며 실제 전체 분포를 대표하지 않는다.**
- 고령 사용자 대상 실제 사용성 검증이 별도로 필요하다.
- **이번 1단계 실행은 Gemini 실제 호출을 포함하지 않는다** — AI 요약 품질, Grounding 근거 적절성, 토큰·응답시간 실측치는 아직 확인되지 않은 상태다.
- 이 시스템은 **사기 탐지**에 최적화되어 있으며, E02(복약 중단 권유)처럼 사기와 무관한 건강상 위해 조언은 낮은 위험 점수로 나올 수 있다 — 설계 목적 밖의 영역임을 사용자에게 안내할 필요가 있다.

## 14. 결론

- **잘 처리하는 범위**: 명백한 사기 조합(사칭+송금, 원격제어, 협박+결제 등)은 규칙만으로 10/10 정확히 RULE_ONLY·danger 이상에 도달했고, Gemini 호출도 0회로 정확히 지켜졌다(가장 중요한 안전 기준 충족). 정상 안내문(금융·택배·안전공지)에서도 명백한 오탐(danger/critical 오판)은 0건이다.
- **아직 신뢰하기 어려운 범위**: (1) "정부"·"혜택"·"발표"·"마감" 같은 지나치게 넓은 단일 키워드가 정책 뉴스·광고·공지에서 경미한 오탐(caution) 또는 불필요한 Grounding 라우팅을 유발한다. (2) 전각 숫자로 개인정보 마스킹을 우회할 수 있다(P1, 우선 수정 권장). (3) AI_SUMMARY·GROUNDED_FACT_CHECK 경로의 실제 품질(요약 자연스러움, Grounding 근거)은 아직 실제 키로 검증되지 않았다.
- **발표 시 시연하기 적합한 사례**: A02(검찰 사칭 삼중 조합), A05(원격제어 탈취) — RULE_ONLY로 즉시 critical 판정되며 Gemini 호출이 전혀 없다는 점을 명확히 보여줄 수 있다. B03(정상 공지, safe)와 대비해서 보여주면 오탐 없음을 함께 시연 가능.
- **다음 개발 단계에서 우선 수정할 항목**: P1 두 건("정부" 키워드 구체화, 전각 숫자 마스킹) → 그다음 실제 `GEMINI_API_KEY`로 이 문서를 갱신해 AI_SUMMARY·GROUNDED_FACT_CHECK 경로의 실제 성능(토큰·응답시간·Grounding 품질·수동 요약 품질 평가)을 채우는 것.

## 자동 측정 vs 수동 검토 구분

**자동 측정**(이번 실행에서 코드로 직접 산출): 모드(plannedMode/executedMode), 위험 점수, 위험 등급, 규칙 신호 코드, 호출 횟수, 응답 시간, 오류 상태(aiStatus). 토큰 사용량·citation 개수는 이번 실행에서는 AI가 호출되지 않아 "측정 불가"로 기록했다.

**수동 검토**(사람이 판단해야 하는 항목 — 이번 1단계에서는 전부 판단 보류): 쉬운 요약의 자연스러움, 고령 사용자 이해 가능성, 위험 설명의 적절성, 불필요한 공포 표현 여부, 사실을 과도하게 단정했는지 여부.

| 항목 | 상태 |
|---|---|
| 쉬운 요약의 자연스러움 | 판단 보류 — AI 응답 없음(키 미설정) |
| 고령 사용자 이해 가능성 | 판단 보류 — AI 응답 없음(키 미설정) |
| 위험 설명의 적절성(규칙 기반 문구는 기존 검증됨) | 적절함 — `RECOMMENDATION` 고정 문구는 과도한 단정 없이 "~일 가능성이 높습니다"·"~확인해 보세요" 형태를 유지 |
| 불필요한 공포 조장 여부 | 적절함 — 고정 문구 검토 결과, 등급별로 과도한 공포 표현 없이 행동 지침 위주로 구성됨 |
| "안전하다"는 확정 표현 사용 여부 | 적절함 — `safe` 등급 문구도 "뚜렷한 위험 신호가 적습니다"로 단정을 피하고, 모든 등급에 안전 미보장 디스클레이머가 항상 표시됨(`ResultView.tsx`) |

실제 Gemini 키 적용 후, 위 "판단 보류" 항목들을 사람이 직접 읽고 재평가해야 한다.
